# 理光 GR IV BT.2100 HLG HDR 照片直出功能技术文档

> **功能分支**: `feat/hlg-photo`  
> **适用机型**: 理光 Ricoh GR IV / GR IV HDF (固件版本 1.11)  
> **适配框架**: [Ricoh-GRMod](https://github.com/Maxwooow/Ricoh-GRMod)  
> **目标槽位**: 图像控制 Slot 22 (`toneId = 22 = 0x16`，“HDR色调”)

---

## 1. 功能概述与核心价值

理光 GR IV 配备了一块高动态范围的 2614 万像素 APS-C 格式 CMOS 感光元件，其 RAW 传感器原始线性动态范围超过 12 档。然而在原厂固件中，机身直出的 JPEG 照片受限于传统的 8-bit sRGB 标准动态范围（SDR）色彩空间，高光信息遭到不可逆的硬性裁切与压缩。

本功能将理光 GR IV 的机身直出能力升级至 **BT.2100 HLG（Hybrid Log-Gamma）原生 HDR 照片模式**：
- **纯硬件管线实时处理**：由机载 Milbeaut 图像处理器全速完成处理，快门零延迟。
- **宽色域与超高动态范围**：直出图片具备 **ITU-R BT.2020** 广色域与 **ARIB STD-B67 (HLG)** HDR 传输特性。
- **跨平台原生 HDR 显示**：完美支持 Apple 全生态（iPhone、iPad、Mac 的 Liquid Retina XDR 屏幕 EDR 高光迸发）、Windows 11 HDR 显示器、Android 原生 HDR 相册以及现代 Chromium 浏览器。
- **RAW 格式 100% 独立保留**：开启 RAW+JPEG 时，RAW（DNG）文件保持传感器原始纯净状态，不受任何影响。

## 2. 槽位架构设计：为什么选择 Slot 22（HDR色调）？

在早期逆向原型开发中，曾临时占用 `Cinema Green`（槽位 19）。而在本次 GRMod 原生深度集成中，方案进行了全面升级，将功能严格锚定在 **Slot 22（“HDR色调”/`HDR Tone`）**：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                            图像控制（Image Control）槽位分布                 │
├────┬────────────────────┬───────────┬───────────────────────────────────────┤
│ ID │ 色调名称           │ 槽位类型  │ 本 Mod 状态                           │
├────┼────────────────────┼───────────┼───────────────────────────────────────┤
│ 11 │ 标准 (Standard)    │ 原厂预设  │ 保持原厂状态（作为中性多轴基准）      │
│ 18 │ 电影（黄色）(CY)   │ 原厂预设  │ 保持原厂状态（支持 GRMod 自定义 LUT） │
│ 19 │ 电影（绿色）(CG)   │ 原厂预设  │ 保持原厂状态（支持 GRMod 自定义 LUT） │
│ 22 │ HDR 色调           │ 原厂预设  │ 改造为 -> BT.2100 HLG HDR 直出模式    │
│ 34+│ 扩展风格 (Styles)  │ 扩展槽位  │ 100% 完美共存兼容 (Style 34..39)      │
└────┴────────────────────┴───────────┴───────────────────────────────────────┘
```

### 核心优势：
1. **完全保全经典胶片色调**：Slot 18（电影黄色）与 Slot 19（电影绿色）100% 保持纯净基线，用户依然可以自由导入自定义 `.xmp` / `.cube` 预设胶片滤镜。
2. **变废为宝**：原厂“HDR色调”是一个人工涂抹感极重、机内几乎从不使用的伪 HDR 色调映射滤镜。将其升级为物理意义上的真 BT.2100 HLG 直出，具有极高的实用价值。
3. **ICONBIN 零字节膨胀**：直接复用机内 `06_ICONBIN.bin` 已有的 HDR 风格图标，不仅视觉一致性完美，且不会使图标数据区膨胀。
4. **多语言统一定名**：机身界面字符串（Text ID 306）在所有 21 种语言下统一定名为精炼的 **“HDR”**。

## 3. 图像处理算法与底层硬件标定

本 Mod 对相机底层 Milbeaut 硬件 ISP 的前置线性色彩矩阵、基底逆补偿色调曲线以及 JPEG APP2 容器注入进行了深度改造：

```
[14-bit Bayer 传感器原始数据]
           │
           ▼
[Milbeaut ISP 硬件图像处理器]
    ├─► 1. 曲线前 Q13 线性色彩校正矩阵 (CCM):
    │      M_HLG = M_709_to_2020 @ M_STD (行和精确等于 8192)
    │      行 0: [ 5546,  2769,  -123 ] -> 和 = 8192
    │      行 1: [  807,  7629,  -244 ] -> 和 = 8192
    │      行 2: [   -9,  1131,  7070 ] -> 和 = 8192
    │
    ├─► 2. 相机内置传感器基底色调曲线 S(lin) [0..16383]:
    │      硬件在应用槽位曲线前会先施加 S(lin)
    │
    ├─► 3. 专属 1D 色调曲线 (256 个 uint16, 14-bit 量化 0..16383):
    │      基于 S^-1 预补偿: curve[i] = round(16383 * HLG( S^-1( i * 64 / 16383.0 ) ))
    │      等效效果: HLG( S^-1( S(lin) ) ) = HLG(lin) (彻底消除双重曲线畸变与压暗)
    │
    └─► 4. 中性多轴色彩查找表重定向:
           T_MA[22] 指针重定向至标准（Standard）的中性 maBlock (0x54049DE8)
           │
           ▼
[ExifJpegWriter 写入器机内 APP2 动态注入 Hook (0x5380BF50)]
    ├─► 检查当前照片 toneId 是否为 22
    ├─► 修正前置 Pentax APP7 预览图长度字段，保证 32 字节边界对齐
    ├─► 注入 576 字节 (0x240) 标准 APP2 ICC_PROFILE 数据段
    │   内嵌 BT.2100 HLG CICP [9, 18, 0, 1] 颜色配置文件
    └─► 将工作区写入指针平移推进 576 字节
           │
           ▼
[SD 卡生成最终 .JPG 成果照片]
    ├─► FFD8 (SOI) + FFE1 (Exif 与缩略图)
    ├─► FFE7 (Pentax 原厂 Screennail 屏幕预览流)
    ├─► FFE2 (APP2: BT.2100 HLG CICP [9, 18, 0, 1] ICC 描述文件)
    └─► DQT + SOF0 + SOS (扫描行图像) + FFD9 (EOI)
```

### 3.1 曲线前 Q13 线性色彩校正矩阵（CCM）
传感器原始色彩基于 Rec.709 标定。为在伽马前完成线性转换至 BT.2020 广色域，我们将相机“标准”色调（`toneId = 11`，存储于 `0x54049850`）的原生传感器校准矩阵 $M_{\text{STD}}$ 乘以 CIE D65 规范下的 Rec.709 $\rightarrow$ Rec.2020 转换矩阵：

$$
M_{709\rightarrow 2020} = \begin{bmatrix}
0.6274039 & 0.3292830 & 0.0433131 \\
0.0690973 & 0.9195404 & 0.0113623 \\
0.0163914 & 0.0880133 & 0.8955953
\end{bmatrix}
$$

将乘积量化为有符号 16 位整数（**Q13 格式，即 $8192 = 1.0$**），并强制对角线补偿保证每行和严格为 8192（确保中性灰阶绝对不偏色）：
- **第 0 行**: `[5546, 2769, -123]`（行和：`8192`）
- **第 1 行**: `[807, 7629, -244]`（行和：`8192`）
- **第 2 行**: `[-9, 1131, 7070]`（行和：`8192`）

### 3.2 256 点 14-bit 逆基底补偿色调曲线（$S^{-1}$ 预补偿）
GR IV 的硬件在调用各槽位色调曲线前，会先经过一段相机固有的传感器基底曲线 $S(\text{lin})$：

$$\text{display} = \text{curve\_c}\big(S(\text{lin})\big)$$

如果直接套用 ARIB STD-B67 公式，曲线将与内置 $S(\text{lin})$ 叠加，造成中间调严重压暗以及高光色调非线性畸变。为了输出精准的物理级 HLG，我们在生成 256 点表时进行了 $S^{-1}$ 逆函数预补偿：

$$\text{curve\_c}[i] = \text{round}\Big(16383 \cdot \text{OETF}_{\text{ARIB\_STD\_B67}}\big(S^{-1}(b_i)\big)\Big)$$

其中 ARIB STD-B67 光电转换函数（OETF）为：

$$\text{OETF}(E) = \begin{cases}
\sqrt{3E}, & 0 \le E \le \frac{1}{12} \\
a \ln(12E - b) + c, & \frac{1}{12} < E \le 1
\end{cases}$$

$$\text{参数：} a = 0.17883277,\; b = 0.28466892,\; c = 0.55991073$$

- 曲线起始值为 `0`，末端索引 255 处精确量化为 `16214`，保留了充裕的 14-bit 高光头顶动态余量（Headroom）。
- 专属 Gamma 描述符中的 `desc[5]` 置为 `0`，彻底关闭原厂二次对比度反卷。

### 3.3 中性多轴色彩表指向
Slot 22 原厂带有多轴色彩饱和度偏移表。Mod 将其 `T_MA[22]` 指针重新定向至标准（Standard）色调的中性平坦表（`0x54049DE8`），消除任何多轴偏色。

## 4. 机内 APP2 色彩配置文件动态注入机制

即便传感器与 ISP 输出了完美的 HLG 信号，普通系统如果没有读取到正确的色彩配置文件，依然会按 sRGB 解码，导致照片严重泛灰。

本 Mod 在相机的 JPEG 写入流程核心函数 `ExifJpegWriter::SetupAppNInfo`（虚拟地址 `0x5380BF50`）处安装了 ARMv7 汇编钩子：
1. **槽位命中检查**：从 `[r4, #0x08]`（常规拍摄）或 `[r4, #0x0c]`（回放/RAW重显）中读取当前照片的 `toneId`。若非 22，直接执行原厂指令并跳回，完全零干扰。
2. **APP7 缓冲区对齐修复**：针对前置的宾得 APP7 Screennail 预览图段，动态修正长度字段，确保下一个段写入起始地址严格处于 32 字节边界。
3. **写入 APP2 标记段**：直接在 `m_workArea` 追加 576 字节（`0x240`）的完整段：
   - 标记：`0xFF 0xE2`
   - 长度：`0x023E`（574 字节）
   - 头标识：`ICC_PROFILE\0\x01\x01`（14 字节）
   - 载荷：532 字节超轻量 ICC 配置文件，包含标准 `acsp` 头与标准 **CICP 标签**（`[9, 18, 0, 1]`，对应 Rec.2020 / ARIB STD-B67 / RGB / Full range 全范围）。
   - 填充：末尾补 2 字节零保证对齐。
4. **推进写入游标**：将工作区写入指针 `[r4, #0x50]` 平移推进 576 字节。后续的 `DQT`、`SOF0`、`SOS` 扫描流自然紧随其后生成。

## 5. HDR Tone Level 0 档位与 SDR 旁路机制

在相机 Slot 22（“HDR色调” / “HDR”）的图像控制参数微调菜单中，原厂提供了 4 项细化调节参数：**饱和度**、**色相**、**明暗对比度**与 **HDR Tone Level**（参数 17，固件内部标识为 `HDR Intense`）。

### 5.1 需求与功能设计
原厂固件中，`HDR Tone Level` 仅支持 `1`、`2`、`3` 三个调节档位（最低只能调至 1）。本 Mod 拓展了该参数的调节下限，增加了 **0 档位**：
- **档位 1、2、3**：完整启用 BT.2100 HLG HDR 照片拍摄（应用 Rec.2020 广色域矩阵、ARIB STD-B67 伽马曲线并动态注入 APP2 CICP ICC Profile）。
- **档位 0**：**完全旁路（Bypass）HDR 效果**。直出纯净的无 HDR 曲线、无色域变换的标准 sRGB SDR JPEG 照片，无需来回切换图像控制槽位即可在标准 SDR 与 HDR 直出之间自由切换。

### 5.2 双层旁路架构与执行流

```
[HDR Tone Level 档位调节]
         │
         ├──► 调至档位 0: 
         │      ├─► ISP 底层管线调度 Hook (0x53912D3C): sl = 0 (标准 Standard 风格)
         │      │     ├─► ToneRecord: 标准 Rec.709 线性色域矩阵 (0x5501ADBC)
         │      │     ├─► GammaDescriptor: 标准 SDR 伽马曲线
         │      │     └─► 标准中性多轴色彩表
         │      └─► APP2 注入 Hook (0x5380BF50): [r1, #0x7b8] == 0 -> 跳过注入
         │            └─► 成果输出: 100% 纯净的标准 sRGB SDR JPEG
         │
         └──► 调至档位 1, 2, 3:
                ├─► ISP 底层管线调度 Hook (0x53912D3C): sl = 22 (HLG 风格)
                │     ├─► ToneRecord: Rec.2020 广色域线性色域矩阵
                │     ├─► GammaDescriptor: ARIB STD-B67 (HLG) 曲线
                │     └─► 标准中性多轴色彩表
                └─► APP2 注入 Hook (0x5380BF50): [r1, #0x7b8] != 0 -> 注入 APP2
                      └─► 成果输出: 原生 BT.2100 HLG HDR JPEG 照片
```

### 5.3 底层逆向与工程实现细节

1. **选项与内部数值映射表 (`0x53DBAD84`)**：
   - 原厂 ROM 中的数组为 `[1, 2, 3, 0]` (`0x00030201`)。
   - 补丁修改为 `[0, 1, 2, 3]` (`0x03020100`)。
   - 使 UI 选项步进索引 `0, 1, 2, 3` 与底层存储的数值 `0, 1, 2, 3` 完全 1:1 对齐，省去繁冗的重映射。
2. **选项总数定义函数 (`GetHdrCuisineHdrIntenseValueCount` @ `0x533BEBF8`)**：
   - `0x533BEC24`: `cmp r0, #3` (`0xE3500003`) -> 补丁改为 `cmp r0, #4` (`0xE3500004`)。
   - `0x533BEC28`: `movls r0, #3` (`0x93A00003`) -> 补丁改为 `movls r0, #4` (`0x93A00004`)。
   - 将选项总数由 3 增至 4，拍摄界面与参数菜单的步进选择器上限自动放开至 3（支持 0..3 四个档位）。
3. **UI 文本格式化函数 (`GetImageControlParameterHdrIntenseAscii` @ `0x5339B5F0`)**：
   - 原厂代码硬编码校验仅接受 1..3，其余值报错。
   - `0x5339B610`: `beq #0x5339B64C` (`0x0A00000D`) -> 补丁改为 `bls #0x5339B64C` (`0x9A00000D`)。
   - 放行无符号 `0..3` 数值直接进入 `snprintf(..., "%d")`，在屏幕与菜单中正常显示 `"0"`、`"1"`、`"2"`、`"3"`。
4. **底层 ISP 渲染管线旁路 Hook (`0x53912D3C`)**：
   - 在相机拍摄显影调度函数中，寄存器 `sl` 存储 `toneId`，`r7` 指向当前照片的参数结构体（`[r7, #0x7b8]` 为当前照片的 HDR Tone Level）。
   - 汇编钩子检查：若 `sl == 22` 且 `[r7, #0x7b8] == 0`，将 `sl` 赋为 `0`（Standard 标准色调），并同步更新栈槽 `[fp, #-0x34] = 0`。
   - 后续获取 ToneRecord 与 GammaDescriptor 时自动取得 Standard（Rec.709 矩阵与 SDR 伽马曲线），彻底旁路 HLG 硬件处理。
5. **APP2 元数据动态注入 Hook (`0x5380BF50`)**：
   - 检查 `[shotStruct, #0x7b8]`。若 Level 为 0，直接分支跳至退出指令，不注入 APP2 ICC Profile，确保输出为纯净标准 sRGB SDR JPEG。

## 6. GRMod 工程体系深度融合

### 5.1 内存空间与 ROM 镜像映射
GRMod 的补丁基准地址为 ROM 物理基址 `0x53000000`。运行时表项（`T_REC_BASE = 0x55053780`、`T_GAM_BASE = 0x55053138`、`T_MA_BASE = 0x55053504`、`NATIVE_TEXT_ROOTS = 0x55002118`）位于内存 RAM 段（`0x55000000..0x55057480`），其在固件 ROM 镜像中的源物理地址为 `RAM_SRC = 0x5437B640`。

本模块通过地址映射转换：
```ts
export function romVa(va: number): number {
  if (va >= 0x55000000 && va < 0x55057480) {
    return 0x5437b640 + (va - 0x55000000);
  }
  return va;
}
```
确保所有指针和表项修改直接写入固件 ROM 镜像对应区域，避免越界崩溃。

### 5.2 文本目录双写保障
为确保无论相机开机读取 RAM 初始表还是读取 GRMod 的扩展文本目录（`TEXT_CATALOG = 0x543D4AC0`），都能稳定显示 **"HDR"**：
- 同时修改 `NATIVE_TEXT_ROOTS` 中的第 306 号文本指针；
- 以及 `TEXT_CATALOG` 扩展表中的第 306 号文本行（涵盖全部 21 种语言）。

### 5.3 扩展布局与特征位管理
HLG Photo 遵循 GRMod 标准扩展特征位管理：
- **特征位定义**：`FEATURE_HLG_PHOTO = 16`（`0x10`）。
- **版本标识**：Revision 3（`GRMODAR3`）。
- **自检白名单机制**：HLG 开启时自动激活 `Patch.grows` 扩展结构，并在 RTOS 末尾元数据中记录特征位。所有修改词与追加范围自动被 `package.ts:grownRanges` 计入合法白名单，100% 严苛通过 `selfCheckGrown` 自检。

### 5.4 完备的组合兼容性
HLG HDR 照片功能与 GRMod 的其它所有功能完全解耦，支持任意组合构建：
- **自定义画幅比例**（如 65:24 宽幅、1:1 方形、4:3、16:9 等）
- **ADJ 拨杆柔焦功能**（关 / 弱 / 中 / 强）
- **拍摄辅助日期时间戳**（含相机原生菜单界面）
- **GR IV Monochrome 黑白预设解锁**（在彩色机身上解锁 6 款纯正黑白预设）
- **扩展图像控制槽位**（Style 34..39）
- **电影黄色 / 电影绿色自定义胶片 LUT**

## 6. 用户界面与操作指南

### 在电脑端 GRMod 软件中
1. 插入相机 SD 卡，或直接打开理光原厂 `fwdc248b.bin` 固件。
2. 进入 **“图像控制” (Image Control)** 页面，在卡片下方找到扩展功能开关区。
3. 开启 **“HLG HDR 照片”** 开关（带有专属 HDR 图标）。
4. 点击写卡或导出固件。

### 在理光 GR IV 机身上操作
1. 开机后按下机身 **“图像控制”** 按钮（或进入拍摄菜单中的图像控制）。
2. 拨动拨轮切换至 **“HDR”** 风格（原 HDR 色调槽位）。
3. 取景并按下快门。
4. 将照片导入支持 HDR 显示的设备即可欣赏真正的 HDR 高光效果。
